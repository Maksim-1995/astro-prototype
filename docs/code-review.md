## Замечание P2: адрес backend после пересоздания контейнера

В [конфигурации Nginx](../deploy/nginx.conf.template), строка 25,
используется `proxy_pass http://backend:8000` без динамического разрешения
DNS. Если backend получит новый IP, а Nginx продолжит работу со старым,
запросы к API и админке могут возвращать 502.

Docker сохраняет имя сервиса при замене контейнера, но адрес может измениться;
клиент должен повторно разрешить имя и переподключиться.
Это описано в [документации Docker Compose](https://docs.docker.com/compose/how-tos/networking/#updating-containers-on-the-network).
Вывод о риске сделан по текущей конфигурации и правилам
[proxy_pass в Nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass).
Сценарий со сменой IP в Docker здесь не воспроизводился.

Исправлена инструкция: после обновления backend выполняется
`docker compose restart nginx`. Полный порядок команд находится
в [инструкции размещения](backend.md#запуск-в-docker).
Динамический DNS в конфигурацию не добавлен, поэтому при обновлении
контейнеров нужно соблюдать этот порядок. Это мера в процедуре размещения,
а не изменение бизнес-логики API.

- `ruff format --check` прошёл.
- `manage.py check`: ошибок нет.
- `makemigrations --check --dry-run`: изменений нет.
- Компиляция Python и `git diff --check` прошли.
- AST-проверка: отсутствующих и нерусских докстрингов нет.

Для повторения из `backend`, после загрузки окружения разработки:

```bash
uv run --group dev pytest
uv run ruff check --config pyproject.toml . ../docs
uv run ruff format --check --config pyproject.toml . ../docs
uv run python manage.py check
uv run python manage.py makemigrations --check --dry-run
```

Проверки покрывают валидацию email и согласия, дубли и ограничение
уникальности в БД, сохранность исходного согласия, права сотрудников,
защиту CSRF, CORS, лимиты по IP и обработку недоступной БД.

## Ограничения проверки

Сборка и запуск Docker/Nginx не проверены: доступ к Docker socket запрещён
и при повторной проверке вне песочницы. Контейнерный сценарий P2 оценён
по конфигурации, не по запущенному стенду.

HTML/CSS/JS сайта в этой правке не изменялись. Браузерные сценарии заново
не запускались; исторический результат от 23 октября приведён
в [backend-qa.md](backend-qa.md). Изменённые Python-скрипты QA проверены
сравнением AST и компиляцией.

Backend по-прежнему требует отдельного внешнего хостинга и настройки HTTPS.
Этот рефакторинг не подключает опубликованную форму к рабочему API.
