# Проверка backend и формы — 23 октября 2026

Окружение: Python 3.12.14, Django 5.2.18, DRF 3.18.3, PostgreSQL 18.6.
Зависимости закреплены в `backend/uv.lock`. Проверки выполнялись на отдельном
локальном PostgreSQL-кластере; пользовательские базы не изменялись.

## API и админка

**56 тестов Pytest прошли на PostgreSQL**, последняя проверка — 3,22 секунды.
Покрыты создание и нормализация email, дубли, уникальность на уровне БД,
явное согласие, серверные дата и версия политики, honeypot, закрытый публичный список,
лимиты по IP, общий DatabaseCache, ошибки healthcheck, права сотрудников,
изменение статуса, неизменность исходных сведений, CSRF и CORS.
Регрессионный тест проверяет Unicode-email, длина которого растёт после lower():
API возвращает 400 вместо ошибки PostgreSQL.

`manage.py check` — без ошибок; `makemigrations --check --dry-run` — изменений нет.
Миграции применены; `collectstatic` собрал 154 файла. Gunicorn запущен с двумя workers.

## Форма в Firefox

**10 браузерных сценариев прошли** через Marionette:

- Без конфигурации поля отключены и запрос не отправляется.
- Новая заявка через настоящий API возвращает 202 и показывает подтверждение.
- Повторная заявка получает тот же ответ; в PostgreSQL подтверждена одна запись.
- Проверяются обязательные email и согласие.
- Ответ 400 сохраняет email и возвращает фокус к неверному полю.
- Ответ 429 сохраняет email и показывает время Retry-After.
- Сетевая ошибка сохраняет данные.
- Двойное нажатие во время отправки создаёт один fetch.
- Таймаут разблокирует форму и сохраняет email.
- При viewport 390×844 нет горизонтальной прокрутки; диалог помещается,
  закрытие возвращает фокус к кнопке открытия.

Ответы 400/429, ошибка сети и таймаут проверены с fetch-fixtures.
Создание и повторная заявка проверены с настоящими API и PostgreSQL.
Использованы технический адрес `example.com` и временный URL политики;
конфигурация опубликованного сайта не подменялась.

Скрипт `docs/beta_form_browser_qa.py` запускает временный frontend на порту 18001,
обращается к API `http://127.0.0.1:18000` и подключается к запущенному Firefox.
В локальном backend должны быть включены заявки, задана тестовая версия политики
и разрешён CORS origin `http://127.0.0.1:18001`.

```bash
firefox --headless --no-remote --createprofile 'astro-beta /tmp/astro-beta-browser-profile'
firefox --headless --no-remote --profile /tmp/astro-beta-browser-profile --marionette --window-size 1440,1000 about:blank
```

В другом терминале из каталога `astro-prototype`:

```bash
python3 docs/beta_form_browser_qa.py
```

## Инфраструктура и ограничения

Пройдены Ruff, синтаксис трёх JS-файлов и `git diff --check`.
Проверен синтаксис Compose и shell-скрипта генерации `config.js`.
Генерация проверена с пустым и обычным URL, кавычками/обратным слешем,
Unicode и переводом строки; неподходящая схема URL отклоняется.

**Сборка и запуск Docker/Nginx не проверены:** нет доступа к Docker socket.
API и база проверены напрямую. Safari, Chromium и физические телефоны не проверялись.
`check --deploy` для локальных настроек сообщает о выключенных HTTPS redirect/HSTS
и техническом тестовом секрете. Production HTTPS, домен, секреты и резервное копирование
нужно настроить на сервере; инструкция — в `docs/backend.md`.

Django API на внешний хостинг пока не развёрнут. Sites не исполняет Django;
опубликованная форма выключена до настройки реального API и URL политики.
